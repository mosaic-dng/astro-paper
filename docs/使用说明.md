# 博客使用说明

你的博客：https://ccio.eu.org/
文章文件夹：https://github.com/mosaic-dng/astro-paper/tree/main/src/content/posts
上传入口：https://github.com/mosaic-dng/astro-paper/upload/main/src/content/posts
部署状态：https://vercel.com/ashs-projects-f56b3363/astro-paper/deployments

## 第一次准备

1. 从 templates/article.md 下载文章模板，在电脑上留一份。
2. 每次写新文章，复制模板，用简短英文名称保存，例如 my-new-post.md。名称决定网址，发布后尽量不要改名。
3. 用 Typora 打开，修改顶部的标题、摘要、日期、标签和分类。把 draft 改成 false 才会在网站显示。
4. Typora 的“偏好设置 → 图像”中，开启“优先使用相对路径”。模板中的 typora-copy-images-to 会让图片放进配套文件夹。新文章叫 my-new-post.md 时，将该项改为 ./my-new-post.assets。
5. 正文从模板的“正文”开始写。不要上传电脑上的全部文件夹，只上传本次文章和它的图片文件夹。

## 发布新文章

1. 在 Typora 修改完成，保存 .md 文件。确认本地图片都正常显示。
2. 打开上面的“上传入口”，点击 choose your files（选择文件）。
3. 上传文章 .md；如果有图片，将同名 .assets 文件夹拖进上传区域。保留文件夹结构，不要单独把图片散放到文章文件夹。
4. 在 Commit changes（提交更改）填写“发布：文章标题”，选择提交到 main，点击提交。
5. Vercel 会自动构建。打开“部署状态”，看到 Ready（就绪）后再访问博客核对。构建失败不会替换上一版正常网站。
6. 若图片没显示，检查是否漏传 .assets 文件夹，或 Markdown 里是否出现 C:\… 等电脑路径。

GitHub 网页限制：单个文件最多 25 MiB，一次最多 100 个文件。图片太大时先压缩；文件太多时，先分批上传图片，最后上传文章。

## 修改已发布文章

1. 在文章文件夹中找到原来的 .md，下载后用 Typora 修改，保持文件名不变。
2. 更新 modDatetime 为修改时间；pubDatetime 保留首次发布时间。
3. 从上传入口上传同名文件，GitHub 会替换旧内容；有新图片时一起上传。
4. 提交说明填写“更新：文章标题”。等部署 Ready 后检查结果。

也可以在 GitHub 打开文章，点击铅笔按钮直接编辑文字，再提交。

## 临时撤下或重新发布

- 打开文章文件，点击铅笔按钮，将 draft: false 改为 draft: true，提交。新部署完成后，文章不会出现在页面、搜索、RSS、分类和标签中，文章地址返回 404。
- 重新公开时改回 draft: false 再提交。
- 公开 GitHub 仓库中的文件和历史仍可被别人查看。私密草稿只放在自己的电脑或 Notion，不要上传。

## 顶部字段怎么填

- title：文章标题，保留引号。
- description：一两句话介绍文章内容，保留引号。
- pubDatetime：首次发布时间，例如 2026-10-14T16:00:00+08:00。
- modDatetime：以后修改文章才填写，格式与发布时间相同。
- category：分类名称，例如“科学上网”“教程”。
- tags：相关标签，例如 ["机场", "推荐"]。
- featured：true 表示首页“必看精选”，false 表示普通文章。
- draft：false 表示发布，true 表示暂不上站。
- ogImage：可选的分享封面，例如 "./my-new-post.assets/cover.png"。没有封面可删除此行。
- typora-copy-images-to：本地图片文件夹，名字与文章一致。网站会忽略这项编辑设置。

未来日期的文章会等下一次网站构建才发布。为了简单，发布时使用当前时间或过去的时间。

## 查看失败原因

进入部署状态，打开最新一项，选择 Build Logs（构建日志）。
看到“图片没有一起上传”时，补传提示的图片。
看到日期或顶部字段错误时，对照模板修正，再提交一次。
不确定时，把日志中的报错文字交给 AI，说明“修复这篇 AstroPaper Markdown 文章，保持原文件名”。

## 恢复上一次内容

打开 GitHub 仓库 → Commits（提交历史）→ 找到修改前的提交 → Browse files（浏览文件）→ 下载该版本的文章，再重新上传。正常部署后，网站恢复旧内容。

整站紧急回退：旧 NotionNext 项目保留在 Vercel 的 notion-next。将 ccio.eu.org 重新绑定到 notion-next，并核对 HTTPS 与首页。日常文章修改通常不需要移动域名。

## 本地备份和迁移记录

迁移原始资料保存在电脑的 .migration-private 文件夹，不会上传。
正式文章及图片在 src/content/posts，可直接复制整个文件夹备份。
docs/migration-map.json 记录旧网址、新网址、Notion 页面和文章文件。
docs/media-manifest.json 记录迁移图片文件及校验值。

Notion 中的原文继续保留，但以后修改 Notion 不会自动更新新博客。
